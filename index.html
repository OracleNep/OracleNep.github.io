写报告这件事

  • 报告一般会把复现步骤、影响范围、风险判断和修复建议写清楚。
  • 遇到通用型或事件型漏洞，会尽量把影响版本、触发条件和修复方式整理到能复核的程度。
  • 公开页面只放必要索引，不展开未公开的利用细节。

项目和提交

这里放一些我确实参与过、以后也可能继续维护的东西。比起只写介绍，能打开仓库、看到提交和讨论会更直观。

JavaSecAtlas

和团队一起做的 Java / Spring 审计辅助工具，主要用来做白盒审计前的整理、规则验证和报告输出。

Java / Spring 审计辅助 SARIF / HTML
  • 会识别 Maven / Gradle 项目，提取 Spring 路由和部分权限注解。
  • 内置 SSRF、XXE、SpEL、路径穿越、文件上传等启发式规则。
  • 我主要参与项目识别、路由提取、规则设计、报告生成和复核流程。

PHP php-src

给 PHP 官方源码仓库提过几个小补丁，主要是配置校验、文档注释和测试相关的维护。

C PHPT Upstream
  • #22261 已合入，补充 ext/intl 错误处理相关的文档和测试注释。
  • #22223 讨论 request_parse_body() 和 max_input_vars 的输入处理一致性。
  • 这个过程也让我更熟悉大型开源项目里的 CI、Review 和小步提交。

Phantom

SoybeanSeclab 团队的浏览器安全扩展，主要用于 SRC 测试前期的信息收集。

JavaScript Browser Extension SRC 辅助
  • 支持基础扫描、递归扫描、批量 API 测试、结果导出和自定义正则。
  • 常见用途是整理前端接口、找敏感信息、看 JS 资源和做授权测试前的资产梳理。
  • 算是团队工具链里比较顺手的一块。
