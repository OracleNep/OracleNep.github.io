01 / 一段完整回答，缺少哪些东西

假设有一道合成附件题：压缩包里放着两个候选字符串，另有一个校验文件说明哪个候选才有效。Agent 成功读取文件，输出了一个看起来很像答案的字符串，然后结束回答。对聊天产品来说，这一轮已经完成；对解题工作台来说，还缺少一次校验、可回查的观察记录，以及把结论交给下一位执行者的方式。

prtseek 的开发围绕这类落差展开。模型负责提出路线和调用工具，程序负责保存材料、约束任务生命周期、记录用量，并要求结论关联真实证据。只把角色提示词写得更详细，无法解决子任务继续运行、旧文件混入新实验或中断后账目缺失这些问题。

这个系列讨论公开代码中的机制与取舍。示例使用合成场景，分析对象是可观察的调用、记录和产物，不把模型生成的过程文字当成真实内部推理，也不以文章中的流程示意宣称解题率提高。

02 / 从 ARTEX 继承什么，向 CTF 收敛什么

prtseek 基于 RuoJi6/ARTEX 二次开发，原始项目来自 Autumn-27/ARTEX，保留 github.com/Autumn-27/artex 模块路径与 AGPL-3.0 许可证。因此，不能把整个 Agent 运行框架描述成从零原创。

项目将工作重心收敛到 CTF：以材料盘点、任务分解、执行验证和交付记录为主线，简化工作台入口。在 Go 后端、SQLite 持久化以及 Next.js 静态前端的基础上，逐步补齐异步协作、共享调用预算、逐轮计量、证据复核和异常结束处理。前端静态资源嵌入 Go 程序，也使“源码可以构建”和“最终二进制里真的有可用页面”成为两项不同的检查。

这一定位决定了后续设计的尺度：先让本地工作流可追踪、可停止、可核验，再讨论更多角色或更复杂的调度。功能数量本身不能回答一次任务为什么成功或失败。

03 / 四个角色围绕交付物协作

角色主要问题应交出的材料
triage题目给了什么，还缺什么？材料清单、约束与待确认事项
command哪些假设值得分别验证？有验收条件的任务、收敛后的结论
solver某条路线能否被实际观察支持？工具证据、脚本、结果与阻塞点
writeup别人能否理解并复核结果？有来源的步骤、产物与验证说明

这里描述的是默认角色的分工，不是每道题都必须经过的固定流水线。一个明确的附件转换任务可以直接交给一个 solver；只有存在互补路线时，并行才有意义。把同一句“继续找答案”复制给多个 solver，通常只会得到重复工具调用和更难合并的叙述。

派发任务时，至少要写出已有材料、需要区分的假设和完成条件。例如“读取校验文件，验证候选集合，返回唯一匹配项及校验观察”，就比“研究一下压缩包”更容易验收。writeup 也必须沿用这些证据，不能在整理文字时把尚未验证的猜测改写成事实。

04 / 运行结束和目标完成，分别建模

后端把 execution 与 outcome 分开保存。前者描述程序运行是否结束、取消、超时或中断；后者描述任务当前是 unverified、partial、blocked 还是 verified。两者回答不同的问题，界面也应分别显示。

合成示例：缺少题目要求的加密附件
execution = completed
outcome   = blocked
criterion = 材料齐全后才能验证候选结果
summary   = 当前只收到说明文件，缺少附件和必要参数

这组状态并不矛盾：Agent 已经完成了本轮检查，并如实指出材料不足。反过来，程序正常结束也可能只获得一个尚未校验的候选，此时不能把 completed 直接映射成“解题成功”。

report_outcome 将结论、验收条件、验证方法、证据引用和产物纳入结构化报告。程序可以拒绝不存在的证据或不可读取的产物，但仍然需要审查“引用的观察是否真的支持验收条件”。这个语义边界会在第四篇继续展开。

05 / 会话目录是协作单元，不是隔离容器

每个子任务有自己的会话及工作目录。创建子任务时，后端把父会话材料目录和根会话的原始题目目录写入任务文本，并要求只读引用已有材料、将产物写进自己的目录。子任务继承父会话实际使用的模型配置，父子关系也落入持久化记录。

这种组织方式能减少多个执行者覆盖同名产物，也方便从结果追溯材料来源。但“只读引用”在这条路径上是任务约定，独立目录本身并不构成操作系统权限隔离。不能据此声称每个 solver 都运行在独立容器，或绝无可能修改父目录。

要继续加强这部分，需要另外设计进程权限、文件访问范围或容器边界，并验证这些限制真正作用于工具执行。当前文章只把会话目录视作材料归属和产物管理机制，不把尚未实现的沙箱能力算进去。

06 / 架构的验收对象应当是失败路径

这套结构最值得检查的场景往往发生在非正常路径：父任务交付时是否还有未收取结果，取消后子任务是否仍写记录，重启后旧会话是否一直显示运行中，报告是否引用了别人的文件。只看一次顺利解出的演示，很难发现这些问题。

后续各篇沿着同一条线继续：第二篇讨论并发任务如何结束；第三篇讨论上下文和用量如何记录；第四篇讨论证据如何约束结论；第五篇把这些状态落到界面；第六篇说明哪些行为可以通过确定性测试验证，哪些结论必须等待真实模型评测。
